# ADR-003 Review (Codex adversarial review, before implementation)

- **Date:** 2026-09-23
- **Scope:** ADR-003 Rev 1.0, read against ADR-004 principles, ADR-005 §4–§7 and MASTER_PLAN §7–§10, §31–§33 and §76.
- **Reviewer:** Codex (`gpt-5.5`, read-only, files inlined). Adjudicated by Claude Code.
- **Codex verdict:** "needs changes" (6 Critical, 8 High, 4 Medium, 1 Low).
- **Outcome:** ADR-003 **Rev 1.1**. 18 findings accepted; 1 accepted in part. Every accepted change has a schema-level test in `internal/registry/schema_test.go`, and the key ones are mutation-checked.

| # | Sev. | Finding | Decision | Rev 1.1 change |
|---|---|---|---|---|
| C1 | Critical | An admin can self-escalate: create a principal, grant it roles, issue it a key, then act as a "second person" | **Accepted** | Role grants are two-person: proposer ≠ approver, and neither may be the grantee. **Bring your own key**: EACP stores only hashes the key holder supplies, so an issuing admin never learns the secret. Credential registration is two-person. |
| C2 | Critical | One human with two principals (or a service principal) defeats "author ≠ activator" | **Accepted** | Human principals have a canonical `subject`, unique per tenant. `admin`, `registry_approver`, `approver` and `operator` are human-only (trigger). |
| C3 | Critical | A free-text `secret_ref` could name another tenant's secret or a platform secret | **Accepted** | Secret refs are tenant-namespaced by construction: the worker resolves `(action.tenant_id, secret_ref)`, and each secret is bound to an endpoint host (Phase 5 obligation). `secret_ref` has a strict format (`CHECK`). |
| C4 | Critical | Contract isn't bound to the tool identity; an endpoint change keeps an old certification | **Accepted** | Connectors and tools are immutable. Each contract stores a DB-computed `fingerprint`, and `CheckCapability` denies with `contract_fingerprint_mismatch` on drift (tested by editing a connector as superuser). MCP schema fingerprints come in Slice C. |
| C5 | Critical | An irreversible or financial tool may declare no idempotency and no lookup, then be retried | **Accepted** | `CHECK unsafe_writes_single_attempt`: any tool that isn't `READ_ONLY` and has `idempotency_mode = none` must have `max_attempts = 1`. Ambiguity still goes to `UNKNOWN_OUTCOME`, never an automatic retry (ADR-004). |
| C6 | Critical | RLS alone doesn't stop cross-tenant references | **Accepted** | Composite `(tenant_id, id)` foreign keys everywhere. Tested: a tenant-B agent naming a tenant-A owner is rejected with `23503`. |
| H1 | High | `CheckCapability` omits the tenant policy pointer lock (ADR-004 principle 7) | **Accepted (clarified)** | ADR-003 §6: `CheckCapability` is necessary, not sufficient. The release boundary locks the policy pointer (ADR-005 §5a). |
| H2 | High | Role and membership eligibility aren't row-locked | **Accepted** | `eacp.assert_role` reads the principal and grant rows `FOR SHARE`; revocation and disabling `UPDATE` them. |
| H3 | High | Agent-key issuance lets one approver impersonate an agent | **Accepted** | Bring your own key, two-person registration, 90-day maximum expiry. |
| H4 | High | Version activation ignores dependency SoD | **Accepted in part** | The activator must differ from the version creator **and** the author of its active allowlist. Contracts are shared per tool, so they aren't coupled to version activation; contract activation is two-person on its own. |
| H5 | High | Owner and group changes open SoD timing windows | **Accepted** | Agents are immutable, owner included. Membership changes are audited and never deleted. Phase 3 must use the union of memberships at request creation and at vote time (recorded in ADR-003 §1). |
| H6 | High | The audit chain is forgeable by the app role | **Accepted in part** | The DB assigns `seq`, `recorded_at`, `prev_hash` and `hash` in a `SECURITY DEFINER` trigger; only that trigger writes the chain head; the hash covers `tenant_id`. **Not solvable here:** a compromised writer can still append false events. Stated as a scope limit; external anchoring is Slice C. |
| H7 | High | The ADR doesn't restate that agents have no network path to connectors | **Accepted** | ADR-003 §5 cross-references ADR-001 §3 and `test/security`. |
| M1 | Medium | `consistency` field is missing | **Accepted** | `reconciliation_consistency` added, with `CHECK`s. |
| M2 | Medium | Lifecycle/terminal rules aren't enforced by the DB | **Accepted** | `agent_versions_guard` enforces the full transition table; the tests cover every (from, to) pair. |
| M3 | Medium | Auth semantics for `REGISTERED` are unclear | **Accepted** | Any non-terminal state authenticates but has no capability; terminal states fail to authenticate. |
| M4 | Medium | `connector.tool` lookup needs canonical, immutable slugs | **Accepted** | Lowercase slug `CHECK`s, uniqueness per tenant (tools per connector), immutable rows. |
| L1 | Low | Authentication-failure logs could leak | **Accepted** | Logs carry a reason code and the credential ID only, never the key (tested). |

## Additional decision made during implementation

- **The actor comes from the transaction, not from columns.** Triggers read `app.actor_id` (set by `storage.SetActor`) and fill every `*_by`/`*_at` column themselves. A client that leaves a stale `state_changed_by` in place therefore can't misattribute a change. Only the schema owner (bootstrap) may act without an actor.
