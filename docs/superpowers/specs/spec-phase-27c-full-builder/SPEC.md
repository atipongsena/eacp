# Phase 27c: the full Agent Studio builder

## Why

The owner selected Phase 27c after the Studio thin slice, Hub and run kill scope. Authors need governed model steps and deterministic choices alongside tool calls, a complete form builder and usable templates. The department gate remains not met; this work uses the recorded fallback and makes no claim of department validation. Deliver the entire phase, then stop before Phase 29.

## Capabilities

- **CAP-1**
  - **intent:** Authors save immutable agents with tool, model, branch and response steps and request their required capabilities.
  - **success:** PostgreSQL validates schema-v2 definitions and all paths, derives exactly their tenant-local tools and models, refuses stale version saves and prevents an author approving their own request. Existing schema-v1 agents still run.
- **CAP-2**
  - **intent:** Approved agents use governed model calls and recover safely after interrupted execution.
  - **success:** Every Studio model call has a fenced run-step intent, one admission and at most one provider request; recovery consumes the retained validated output or fails closed without another call. Budgets, revoked credentials, version replacement and run/model kills remain effective.
- **CAP-3**
  - **intent:** Authors choose fixed paths from typed input or earlier output values.
  - **success:** Both branch outcomes reach a response, only the chosen path executes, and missing values or incompatible operand types stop execution. The model cannot supply a step id, tool name or executable condition.
- **CAP-4**
  - **intent:** Authors build, test and submit agents through English and Thai forms with understandable approval requirements.
  - **success:** The page provides basics, inputs, step editors, test and capability review; draft tests make no external calls. An approved owned version can run a real LLM preview with sample tool outputs, and PostgreSQL refuses every tool action from that preview. All writes use confirmation and existing console security rules hold.
- **CAP-5**
  - **intent:** Authors start from concrete templates and operators can demonstrate the full governed path on both supported deployment environments.
  - **success:** Leave balance, leave request triage and procurement request triage have matching page/demo fixtures. Compose and Kubernetes demos exercise two-person capability/key approval, both branch outcomes, model and run containment, refusal, recovery and secret isolation.

## Constraints

- ADRs are authoritative. Amend ADR-033 to Rev 1.4, ADR-028 for the builder, ADR-031 for the narrow typed Studio-output exception and ADR-029 for gateway packaging before claiming delivery.
- PostgreSQL owns validation, capability derivation, run progress, leases, admission, hard budgets and kill authority. Studio and the runtime remain clients.
- No enterprise/provider credential in an agent definition, runtime, output, log, journal, message or screenshot. Only the gateway holds provider credentials.
- Schema v2 has at most 20 forward-only nodes, no loops; every reachable path terminates and each output reference names an earlier node present on every path reaching the consumer.
- One non-streaming provider call per LLM node; no provider retry, model fallback, model-selected tool or schema network resolution.
- A typed Studio output is at most 65,536 bytes, accessible only to the live lease holder, cleared on terminal run state or deadline and excluded from audit content. Prompts and full provider envelopes are never stored.
- Raw SQL tests run as `eacp_app`; new tables, policies and definer functions enter the RLS catalogue. Use TDD and `-race`, fresh validation and the full suite because shared code changes.
- Preserve paired English/Thai user documents, literal translations, route/sink checks, template parity and screenshots generated by the repository script.
- No new dependency or version upgrade. No download, external write, production deployment or CI workflow change is authorized by this draft.

## Non-goals

- Phase 29/inbound A2A, global kills, SSO, schedules, chat triggers, webhooks, canvas, loops, retrieval, co-authoring or cross-tenant sharing.
- Provider structured-output guarantees, streaming Studio generation, automatic model fallback or replay of an admitted LLM request.
- Automatic budget/price provisioning, capability approval, key approval or Hub publication.

## Success signal

On compose and a development Kubernetes cluster, an author builds a triage agent from a form; a second person approves its capabilities and key; a colleague runs it. Its JSON model output selects a fixed branch, its chosen tool action goes through normal governance and its answer reaches only the requester. A run kill stops its in-flight model call and no resumed replica repeats it.

## Assumptions

- Use the existing pinned Go libraries and both gateway provider shapes. Model output follows a small closed JSON-schema subset, validated after receipt without rewriting a gateway request.
- Real model preview requires an approved immutable version owned by the author. Draft preview uses samples for both tools and LLMs. This conservative amendment to program section 7 preserves the approval boundary.
- Template model/tool names are explicit deployment prerequisites selected by the author; copying a template grants nothing.

## Open Questions

- Implementation requires the owner's permission for schema migrations, Studio-specific admission/preview authorization, non-secret runtime gateway configuration and compose/Helm/development Kubernetes infrastructure changes described in `design.md`. Accepted ADRs remain unchanged until that decision.
