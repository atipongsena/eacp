## 1. Owner decisions (2026-09-30)

- **27a-3 is split in two.** 27a-3a (this document): the template's MCP tool, packaging and a demo driven through the
  API. 27a-3b: the `/studio/` page (the form, status, approvals and the run view), its Thai text and screenshots.
- **Approvals live in `/studio/`** (27a-3b). **The template is static in the page** (27a-3b); this phase fixes it as

## 2. What 27a-3a delivers

The leave-balance path runs for real on the compose stack: a Studio agent calls a certified MCP tool through the
action path and answers its requester. Nothing in the API, the schema or the runtime changes.

## 3. Design

### 3.1 The template's tool (`internal/fakemcp`)

- `get_leave_balance`: `inputSchema` `{employee_id: string}` (required), `outputSchema` `{days: integer}` (required),
  `annotations.readOnlyHint` true.
- A call answers `structuredContent: {"days": N}` and a text item `"<id> has N days of leave left."`. N is fixed
  per id: `E-1` 12, `E-2` 3, any other id 0. The id `ERR` answers `isError: true` ("employee not found").
- The server answers `get_leave_balance` only when its current tool list names it, as it answers `get_po` only
  for `get_po`. The default list stays `get_po` alone, so the Slice C demo is unchanged.
- The tool list lives in `deployments/docker/fakemcp/hr-tools.json`, read by a second instance.

### 3.2 Packaging

- **Image:** the Dockerfile builds `./cmd/agent-runtime`; both the compose image and the release image ship
  `/agent-runtime`. `scripts/ci/release-binaries.sh` and `test/opensource`'s release list name it.
- **Compose:**
  - `fakemcp-hr`: the fakemcp binary on the `erp` network with `hr-tools.json` read-only and its own verifier token
    (`fakemcp-hr-token.dev`, generated by `prepare_fakeerp_token.py` from the manifest, git-ignored). The worker's
    manifest binds `hr-mcp` at `fakemcp-hr:8091` to the Studio demo tenant `…00f5`.
  - `agent-runtime`: profile `studio` (a plain `up` does not start it before its key exists), network `agents`
    only, `EACP_API_URL=http://controlplane-api:8080`, and the volume `studio_runtime` mounted read-only at
    `/run/studio` holding `master` and `keys`. No database URL, no secret file, no other network.
- **Compose security tests** (`test/security`, a created but not started container): the runtime is on `agents`
  only, holds neither connector nor provider secrets, has no `EACP_DATABASE_URL`, mounts `/run/studio` read-only;
  every other service lacks `EACP_STUDIO_MASTER_FILE`; `fakemcp-hr` refuses a call without its token.
- **Helm** (`studio.enabled`, default false):
  - `studio.masterSecret` (key `master`) and `studio.runtimeKeySecret` (key `keys`) name existing Secrets; the chart
    refuses `enabled` without both and renders no value;
  - a Deployment `<release>-agent-runtime` (component `agent-runtime`, its own ServiceAccount with no token, the
    hardened pod and container, probes, `/tmp`), `EACP_API_URL=http://<release>-api:8080`,
    `EACP_STUDIO_MASTER_VERSION` (`studio.masterVersion`, default `v1`), the Secrets mounted read-only at
    `/run/studio`;
  - a NetworkPolicy: no ingress, egress to the API's pods on 8080 only (DNS through the shared policy); the API's
    policy admits the runtime even when `api.ingress.from` is narrowed;
  - `studio.env` is validated like the other components' (no database URL, no secret files, no reserved names).

### 3.3 The demo (`DEMO=S`, `test/demo/studio_test.go`)

Tenant `…00f5` (Wonka; the A2A demo already uses the name Initech). Steps, each logged:

1. **S0.** The tenant with alice and bob as admins; erin (registry editor), rita (registry approver), otto
   (operator), stella (HR, `studio_author`), carol (not in HR); the runtime principal `studio-runtime` (service,
   `studio_runtime`) and its key; an allow policy.
2. **S1.** Connector `hr-mcp` (MCP, `http://fakemcp-hr:8091/mcp`); the worker's scan discovers
   `get_leave_balance`; erin certifies it READ_ONLY, one attempt, keeping results for 10 minutes; rita activates it.
3. **S2.** The runtime starts with a random master (never on disk in the repository) and its key.
4. **S3.** stella saves the template (`test/demo/testdata/leave-balance.json`); rita approves it; the runtime
   proposes the version's key; rita sees it in the Studio queue and approves it. A run started earlier fails
   `credential_pending`.
5. **S4.** stella runs it for `E-1` and reads "You have 12 days of leave left."; carol is refused (403); rita sees
   the run without its answer; fakemcp-hr's log holds one call naming no argument.
6. **S5.** A run for `ERR`: the uncertified `isError` is ambiguous, but a `READ_ONLY` contract treats an
   ambiguous read as retryable; with one attempt the action ends `FAILED` (retry budget exhausted) and the
   run `FAILED action_failed`. (Corrected during implementation: the first draft expected `UNKNOWN_OUTCOME`.)
7. **S6.** otto revokes every Studio key; a new run fails `credential_pending`.
8. **S7.** The scan: no master, derived key (derived again from the master and the recorded credential ids), runtime
   key, input canary or answer appears in any API response, service log (the runtime's included) or database dump;
   the journal verifies.

`scripts/demo.sh` accepts `S`; on Kubernetes the demo skips. `docs/DEMO.md` and `DEMO.th.md` gain the section.

## 4. Tests (failing first)

- `internal/fakemcp`: the tool answers with valid structured content, `ERR` is a tool error, a server without the
  tool in its list refuses it, `hr-tools.json` parses and names the tool with its schemas.
- `test/helm` (`EACP_HELM_REQUIRED=1`): off by default; refused without the Secrets; the Deployment is hardened and
  mounts only its two Secrets; the NetworkPolicy; the API admits it under a narrowed ingress; `studio.env` refusals.
- `test/security` (`EACP_COMPOSE_TEST=1`): as in 3.2.
- `test/opensource`: the release list.
- The demo itself (`scripts/demo.sh`, `DEMO=S`).

## 5. Out of scope

The page (27a-3b), a Studio run on Kubernetes, Vault as the master's source, and changes to the API or the schema.
