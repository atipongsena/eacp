# Phase 25a — Governed A2A delegation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An agent delegates a task to a remote A2A 1.0 agent through EACP: discovered, certified, governed, sent at most once, observable.

**Architecture:** `a2a` is a third connector protocol. Discovery reuses ADR-023's scan machinery (generalised from `mcp` to "discovered protocols" in one migration) with a per-protocol `Discoverer`; each A2A connector has one discovered tool, `delegate`, certified over the whole Agent Card. Execution is a new worker connector (`internal/connector/a2a`) that sends one `SendMessage`, follows the task with `GetTask`, classifies, and cancels on interruption; unfinished work is an unknown outcome for a human, with the remote task id recorded as `remote_reference`.

**Tech Stack:** Go 1.x stdlib (net/http, encoding/json), PostgreSQL (goose migration 00023), `governance.Canonicalize` (RFC 8785), `github.com/a2aproject/a2a-go/v2` v2.6.0 as a **test-only** interop dependency.

**Spec:** `docs/superpowers/specs/2026-09-27-a2a-connector-design.md` (ADR-030 records it).

## Global Constraints

- A2A protocol version `1.0`, JSON-RPC binding only; methods `SendMessage`, `GetTask`, `CancelTask`; header `A2A-Version: 1.0`; card at `/.well-known/agent-card.json`.
- The one discovered tool is `delegate` (`remote_name` and EACP name); its definition is `{"name":"delegate","inputSchema":<§3.3 schema>,"agentCard":<card minus iconUrl, documentationUrl>}` in RFC 8785 form; display is `{"iconUrl":…,"documentationUrl":…}` (members present only when the card has them).
- The card's JSON-RPC 1.0 interface `url` must equal the connector endpoint **byte for byte** (Ruling at plan time: exact equality, no normalisation; a trailing-slash difference fails the scan `interface_mismatch`).
- Limits: card 256 KiB; JSON-RPC response 1 MiB; skills ≤ 200; task/message id 1–256 of `[A-Za-z0-9._:-]`; `remote_reference` 1–512 of the same class; `text` 1–65 536 characters.
- Polling: `GetTask` after 1 s, doubling to at most 5 s; `CancelTask` budget 2 s, sent once, best effort.
- Error classes are exactly those of spec §3.4; certifiable no-effect classes: `a2a_rejected`, `connection_refused_before_send`, `unauthorized`, `a2a_rpc_<1–6 digits>`.
- Never log, store or journal a credential, a payload, a message part or an artifact; log ids, states, counts and SHA-256 digests only.
- No redirects, no proxy, credential only through `worker.Secret.Authorize` (last header step) and only to the connector's host.
- Commit as the user only; no Co-Authored-By trailer. Tests first; `-race`; PostgreSQL tests with `EACP_TEST_ADMIN_DSN`.

## Review Focus

1. **A `GetTask` reply for a different task id, or with an unknown state** — refuse as `invalid_response` (Ambiguous); polling stops at the first terminal or interrupted state; Task 4 tests both.
2. **A kill or cancellation while polling** — the call ends Ambiguous `a2a_interrupted` and exactly one `CancelTask` goes out with its own budget even though the call context is dead; Task 4 and Task 7 test it.
3. **An oversized or never-ending response body** (a remote agent streaming SSE at the JSON-RPC URL) — the 1 MiB budget and the call deadline end it as Ambiguous; Task 4 tests the limit.
4. **An uncertified `a2a_rejected`** — the worker downgrades it to Ambiguous (`UNKNOWN_OUTCOME`), never `FAILED`; Task 7 covers both contracts.
5. **A card whose interface points at another host or path, or uses v0.3 fields only** — the scan fails and nothing is sent; Task 3 tests each.
